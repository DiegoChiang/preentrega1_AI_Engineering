Guía operativa de Redis para idempotencia

El clúster Redis conserva claves de idempotencia de la API de pagos durante 24 horas. Cada clave
relaciona un identificador enviado por el cliente con el resultado de la primera operación. La
aplicación nunca debe repetir un cargo si encuentra una clave válida.

La métrica redis_memory_used_ratio genera una advertencia al superar 0,80 y una alerta crítica al
superar 0,92 durante cinco minutos. La política de expulsión configurada es volatile-lru. Solo las
claves con expiración pueden ser eliminadas por presión de memoria.

Ante una alerta de memoria, identificar primero las claves sin TTL con `redis-cli --scan` y una
muestra controlada de `TTL`. No ejecutar `KEYS *` en producción porque bloquea el servidor. Si
existen claves de idempotencia sin expiración, corregir el productor y aplicar expiración en lotes
pequeños.

Un failover puede producir un intervalo breve de errores de conexión. Los clientes usan backoff
exponencial y un máximo de tres reintentos. Si la indisponibilidad supera dos minutos, la API debe
rechazar temporalmente nuevas operaciones con HTTP 503 para evitar cargos duplicados. Las consultas
de pagos existentes pueden continuar desde PostgreSQL.

Después de la recuperación, comparar los identificadores de operación de PostgreSQL con las claves
de Redis creadas durante la ventana del incidente. Cualquier posible duplicado requiere revisión
manual antes de efectuar reembolsos.
